## 五、已知限制（不修复，属设计边界）

1. LLM 额度耗尽时，依赖生成式模型的回答任务标记为 failed（提示充值）；确定性功能（配队/自查规则/规划/检索）不受影响
2. 官方共现历史数据对"合格但非最优"队友的排序仍有影响（知识分已压制至体系层以下）
3. 观测元数据（实战使用率）采集管线已注册但数据未回填，评分自动降级不掺实战先验
4. 探针脚本的 openapi 路由发现返回 0（openapi 挂载路径与探针假设不一致），路由发现改用手写用例清单覆盖

## 七、容器恢复说明（2026-08-31 补记）

测试收尾时使用了 `docker compose down`（会移除容器定义），导致用户视角"容器消失"。
数据层无任何损失：数据库/知识库均在命名卷（postgres_data 等）中，`down` 不带 `-v` 不影响卷。
恢复流程（已验证）：启动 Docker Desktop → `docker compose up -d postgres etcd minio milvus-standalone bge-model-service` →
容器重建并自动挂回数据卷，账号/会话/社区角色全部完好。
经验教训：日常开发停止容器应使用 `docker compose stop`（保留容器定义），`down` 仅用于明确需要重建时。
