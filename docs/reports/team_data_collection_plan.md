# 配队精细评分数据补充方案

## 结论

现有资料足以建立“可复现的机制评分”，但不足以直接宣称精确的全角色实战强度。数据应拆成三层，避免模型把假设、游戏事实和社区统计混为一谈。

1. **游戏事实层**：角色技能、基础速度、终结技能量、技能回能、战技点消耗、敌人弱点和抗性。
2. **项目实验层**：统一练度、轮转策略、三个合成敌人场景及蒙特卡洛模拟结果。
3. **外部统计层**：混沌回忆、虚构叙事、末日幻影的版本化使用率、队伍使用率、轮次或分数与样本量。

## 已建立的数据底座

- `docs/team_benchmark/benchmark_assumptions.json`：统一练度和模拟条件。
- `docs/team_benchmark/scenarios.json`：单体、双精英和五目标三种合成场景。
- `docs/team_benchmark/source_registry.json`：来源、版本、统计日期、样本量和使用限制。
- 本地 Nanoka 4.4.51 快照已包含角色速度、终结技能量及大量技能的 `sp_base`、`bp_need`、`bp_add` 字段。
- 怪物资料虽然不再在用户智库中展示，但可作为内部模拟数据；当前清单包含 628 条完整记录。

2026-07-28 本地字段审计结果：

| 数据 | 文件数 | 具备所需字段 |
|---|---:|---:|
| 角色档案 | 97 | 96 份包含终结技能量，97 份包含战技点/技能回能字段 |
| 怪物档案 | 628 | 624 份包含弱点、属性抗性或控制抗性字段 |

缺少字段的档案在模拟中必须进入 `Filtering`，不能由大模型补造。

## 可自动完成

### 1. 静态角色机制抽取

从本地角色 Markdown 生成 `character_combat_parameters.json`：

- 基础速度、嘲讽值、终结技能量。
- 普攻、战技、终结技、天赋及特殊技能的回能。
- 单次行动战技点净变化。
- 行动提前、速度增减、能量恢复、解除控制、治疗和护盾关键词。

带条件或随机性的技能保留表达式和条件，不强行折算为一个常数。

### 2. 轮转计算

为每名角色保存至少一条人工可审核轮转，例如：

```json
{
  "character_id": "1101",
  "rotation_id": "skill_basic_repeat",
  "actions": ["skill", "basic", "skill", "basic"],
  "skill_point_delta": 0,
  "energy_gained": 100,
  "action_value": 400,
  "assumptions": ["未受击", "未触发击杀回能"]
}
```

系统据此计算整队战技点最低水位、终结技间隔、速度轴冲突和行动提前收益。受击回能、击杀回能及随机目标技能必须通过多次模拟输出区间，不能只输出平均值。

### 3. 三场景模拟

同一队伍分别运行单体、双精英、五目标，再区分弱点匹配与不匹配。最终保留：

- 输出或关卡分数。
- 战技点最低值与溢出次数。
- 每名角色终结技平均间隔。
- 增益/减益覆盖率。
- 治疗、护盾和解除控制覆盖。
- 失败率与随机种子数量。

## 需要外部统计但可以定期人工导入

Prydwen 当前公开页面提供模式、版本、日期、样本量、角色/队伍使用率和平均轮次或分数。第一版建议每个版本人工导出一次快照，不编写高频爬虫：

- 混沌回忆：`https://www.prydwen.gg/star-rail/memory-of-chaos`
- 虚构叙事：`https://www.prydwen.gg/star-rail/pure-fiction`
- 末日幻影：`https://www.prydwen.gg/star-rail/apocalyptic-shadow`

外部统计只能充当实战先验：

- 使用率不能直接等于强度。
- 不同模式、版本、层数不能横向合并。
- 平均轮次若同时计算上下半，必须保存该限制。
- 新版本暂无统计时回退到机制模拟，并明确标记“尚无同版本实战样本”。

## 不建议自动采集

- 批量扫描玩家 UID 或采集非公开账号数据。
- 没有版本、日期、层数和样本量的榜单截图。
- 将攻略作者的主观评级转换为精确数值。
- 使用大模型猜测技能覆盖率、速度轴或治疗量。

## 推荐评分结构

第一阶段不改变现有确定性基础分，只增加两个独立维度：

- `mechanical_simulation_score`：统一练度与三场景模拟，0–100。
- `observed_meta_score`：同版本终局统计，0–100；没有同版本样本则为 `null`。

最终排序建议：

```text
基础配队合法性通过
→ 机制模拟分 60%
→ 同版本实战先验 25%（缺失时按比例重新归一）
→ 来源覆盖与置信度 15%
→ 大模型仅解释、比较和过滤异常，不直接改数值
```

喜欢角色继续不参与基础强度分，只在阵容合法时生成额外尝试队。

## 仍需人工确认

1. 是否接受 `benchmark_assumptions.json` 中的零星魂、非限定光锥和 24 个有效副词条基线。
2. 每名角色的默认轮转策略，尤其是自动战技、强化普攻、忆灵和欢愉角色。
3. 4.4 版本统计尚未公开时，是否允许界面显示 4.3.1 统计并明确标注“跨版本参考”。
4. 角色 ID `1501` 的火花/花火冲突必须先修正，才能进入模拟与统计名称映射。
