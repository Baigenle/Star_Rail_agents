# 配队评分继续精细化所需数据

当前可解释基础分为：

- 定位完整性：40%。
- 机制标签协同：30%。
- 已规范化配队共现：20%。
- 属性协同：10%。
- 喜欢角色：0%，只生成额外“猜你喜欢尝试队”。

要从“机制匹配分”提升到更接近实战的“强度评分”，需要按版本补充以下结构化数据。

## 最小必需数据

每名角色提供：

```json
{
  "character_id": "角色 ID",
  "game_version": "4.4",
  "role": ["dps", "support", "sustain"],
  "mechanics": [
    {
      "tag": "action_advance",
      "value": 50,
      "unit": "percent",
      "target": "single_ally",
      "condition": "施放战技",
      "uptime": 1.0
    }
  ],
  "skill_points_per_rotation": 1,
  "energy_per_rotation": 30,
  "estimated_turns_per_ultimate": 3,
  "recommended_speed": 160
}
```

## 推荐补充数据

- 统一练度假设：角色等级、行迹、星魂、光锥叠影和遗器词条。
- 三种敌人场景：单体、双精英、五目标；对应弱点、抗性和控制抗性。
- 每套队伍的战技点收支、能量循环、速度轴和行动提前量。
- 混沌回忆、虚构叙事、末日幻影的版本、层数、使用率、平均轮次与样本量。
- 角色的增益覆盖率、减益命中条件、治疗/护盾量和解除控制能力。
- 来源 URL、统计日期、游戏版本及数据样本量。

## 不建议作为评分依据

- 单纯的社区热度、角色喜爱度或抽取率。
- 没有版本、练度和样本量的“强度榜”。
- 只记录最终队伍、没有敌人环境和轮次的数据。
- 将星魂限定机制当作零星魂基础能力。

在这些数据补齐前，模型只负责解释和复核，不能修改确定性基础分，避免把语言模型的主观判断伪装成精确数值。
